Recommendations

  1. Security protocol (FAIL) – Set security mode to WPA3-Personal (SAE), or WPA2-Personal (AES) if some devices lack WPA3.
    Why: Obsolete protocols can be broken quickly; modern ones resist offline guessing and eavesdropping.
  2. Wi-Fi passphrase (FAIL) – Use a long random passphrase or a 4-5 word passphrase; never reuse it elsewhere.
    Why: Short or reused passphrases can be guessed offline from a captured handshake.
  3. Router admin account (FAIL) – Set a strong, unique administrator password (and rename the admin user if possible).
    Why: Default credentials are public and let anyone on the LAN reconfigure the router.
  4. Firmware (FAIL) – Update from the manufacturer's official site and enable update notifications.
    Why: Old firmware carries publicly known vulnerabilities.
  5. Remote management (FAIL) – Disable remote/WAN management unless operationally required (then restrict by IP + VPN).
    Why: Exposes the router login to the Internet.
  6. WPS (FAIL) – Disable WPS in the wireless settings.
    Why: WPS PIN pairing has known design weaknesses that enable brute force.
  7. Guest network (FAIL) – Enable a guest network and turn on client / AP isolation.
    Why: Visitors should not reach trusted devices (PCs, NAS, printers).
  8. Connected clients (FAIL) – Review the client list; change the Wi-Fi passphrase if an unknown device is confirmed.
    Why: Unknown clients may indicate unauthorised access.
  9. Encryption (WARN) – Select AES / CCMP only and disable TKIP.
    Why: Mixed TKIP+AES mode lets weaker clients negotiate weak encryption.
  10. Admin interface transport (WARN) – Enable HTTPS for the router admin page where available.
    Why: HTTP administration sends credentials in clear text on the LAN.
  11. Protected management frames (WARN) – Enable PMF / 802.11w (required for WPA3).
    Why: Without PMF, deauthentication frames can be forged to disrupt clients.
  12. UPnP (WARN) – Disable UPnP if no application requires it.
    Why: UPnP lets devices open inbound ports automatically.
  13. SSID naming (WARN) – Choose a neutral SSID that has no personal or vendor information.
    Why: Default SSIDs hint at the router model and its known weaknesses.

Assessment limited to a network owned by the assessor or covered by explicit authorisation. A configuration review cannot guarantee a network is fully secure.
